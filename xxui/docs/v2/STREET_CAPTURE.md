# 手机采集与实拍路线巡查

先定位村庄并建立档案，目标、范围、关注事项都可以留空。进入“采集与分析”，填写一条路线的名称，沿途逐站拍照。在拍摄地点点击“获取当前位置并上传”，浏览器申请定位权限后，将照片、WGS84 坐标、定位精度、定位时间、上传时间和说明保存到私有材料存储。

选择旧照片时也只记录上传位置，不伪造照片拍摄时间。请在原拍摄地点上传；当前版本不解析 EXIF GPS。单张支持 JPEG、PNG、WebP，最大 15 MB。图库显示同一路线的照片，可上一站、下一站浏览。

点击“让 AI 沿这条路线巡查”，一次选取当前路线全部照片（最多 12 张，较长路线分段命名）。后台按保存顺序逐张调用 CodeBuddy 视觉模型，保存每站图片 ID、观察、疑似影响、核查建议。页面每两秒更新，完成或取消后停止查询；历史记录可重新打开，不重新调用模型。不能读到图片、CLI 超时或格式校验失败会明确失败，允许重新发起。

## 访问与运行

- 手机需要 HTTPS 地址及已登录的项目账户，允许相机/图库和定位权限。电脑的 localhost 不是手机的访问地址；普通局域网 HTTP 不具备定位条件。
- 将网页与业务服务通过同一 HTTPS 域名反向代理，`/api` 转发业务服务。配置 `WEB_ORIGINS` 与认证地址为实际域名，保持鉴权和私有材料访问。现有 compose 与运维说明负责数据库及 worker 启动。
- 服务启动前执行 `npm run db:migrate`，新增 `street_photos` 数据表。
- 显式配置 `CODEBUDDY_VISION_MODEL=hy3`；文字咨询仍使用 `CODEBUDDY_MODEL`。执行器通过 stream-json 传送图片，不开放 shell 或数据库工具。图片内容不写入运行日志。
- `/api/v1/projects/:project/street-photos` GET 列出采集点，POST 接收 multipart；先提交 metadata JSON，再提交 file。metadata 包含 route、lat、lng、accuracy、located_at、note、allow_model=true。创建巡查使用 `/runs` 的 type=streetwalk、photo_ids 数组。

## Limitations

这是按上传顺序排列的定位照片路线，不是自动拼接的 360° 全景，也不是已经核验连通的道路图。定位坐标保留 WGS84，不直接叠加到 GCJ-02 地图。视觉观察不能替代实测、结构鉴定或工程判断；未拍区域不生成事实。照片及定位资料留在私有服务端，不随源码上传 GitHub。
