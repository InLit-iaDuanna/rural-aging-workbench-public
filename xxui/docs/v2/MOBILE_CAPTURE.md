# 独立手机采集端

入口 `/collect`。桌面工作台右上角“手机采集”也可进入，带入当前村庄。手机端只采集，不要求描述问题，也不会自动运行 AI。

## 操作

1. 登录并选择已有真实村庄，填写本次路线名称。
2. 选择拍照间隔（10、30、50、100 米，默认 30）。点击“开始定位”。
3. 腾讯底图显示蓝色当前位置和 GPS 采样线；原始坐标保留 WGS84，展示前通过腾讯官方接口转成 GCJ-02。
4. 第一站可直接拍照。以后按距上一站的直线间隔提示，扣除两个定位点的误差半径；不会将 GPS 抖动累计为走路距离。也可随时手动补拍。
5. 打开后置相机后点击“拍摄并保存当场位置”。位置超过 15 秒未更新时不能拍摄，需等待新定位。
6. 照片先存设备 IndexedDB，点击上传发送到私有业务服务。上传成功清理本机副本；失败留在队列中，可重试。重试复用同一采集编号，服务端不重复生成照片。
7. 点击地图的绿色照片点或路线站号浏览照片，可上一站、下一站查看。

保存字段：照片 JPEG、拍摄时间、定位时间、经纬度、精度、路线名、拍照间隔、现场说明、设备提供的速度/海拔/移动方向（缺失为 null）、最近一段 GPS 采样（最多 600 点）。移动方向不代表镜头朝向。GPS 轨迹为采样记录，不代表道路已核验连通。采集端 `allow_model=false`，不自动授权视觉分析。

## 访问条件

手机需要可访问的 HTTPS 域名、相机与定位权限；不能把电脑 localhost 当成手机地址，普通局域网 HTTP 也不能提供安全定位/相机能力。服务端保留项目鉴权。现有线上前端尚需接入实际运行的业务主机后才能手机外网采集。

页面需保持前台；浏览器锁屏或进入后台可能暂停定位。未上传照片存在当前浏览器，清除站点数据会丢失。页面刷新后重新登录并选中原项目、路线，可读出本机待上传照片。路线上的定位采样随照片保存；尚未拍照的一段采样只在当前页面。

## 街景接入研判（2026-09-10）

- 腾讯：当前采用腾讯 JSAPI GL 地图、GPS 坐标转换和自有照片点。检索到了旧街景 URI/接口资料，但本次未能从腾讯当前官方页面验证其可用性和权限，不能把历史接口当成已接通的现行街景服务。当前 GL skill 的接口目录未提供街景模块。
- 百度：[全景静态图 API](https://lbs.baidu.com/docs/webapi?title=viewstatic%2Fviewstatic-base)有官方现行文档，能按覆盖地点展示已有全景，需另配百度授权与 Key。它不能替代用户自采照片。
- Mapillary：[官方上传说明](https://help.mapillary.com/hc/en-us/articles/115001472029-How-can-I-upload-imagery-to-Mapillary)提供带位置的街景影像上传方案。需要单独评估平台托管、账户、许可及项目覆盖，本轮没有向其传输照片。
- Pannellum：[官方教程](https://pannellum.org/documentation/overview/tutorial/)可以自托管浏览真实等距柱状全景图。它是全景浏览器，不会把几张普通照片自动重建成真实 360° 街景。

本轮确定：腾讯底图 + 私有定位照片采集 + 站点浏览。后续有实际 360° 图片时再接全景浏览，不合成不存在的村庄画面。

## 验证范围

距离算法、过期定位拒绝、元数据保存和重复上传有自动测试；腾讯 GPS 转换接口实测返回成功；浏览器检查独立路由与手机布局。手机真机的 GPS、相机、后台暂停和户外定位精度仍需实机验收。
