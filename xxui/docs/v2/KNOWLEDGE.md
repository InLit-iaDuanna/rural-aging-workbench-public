# 适老化资料与 AI 使用

当前目录实际找到两类文字来源：项目总纲与调试工作区 Word 方案（PDF 为同一方案的另一格式）。已提取 82 个原文片段，保留来源文件、章节/段落定位、资料性质和未核验标记。另有 23 张效果图，未发现实施地点、时间与效果说明，因此没有将图片提升为工程证据。

在工作台「调试 → 适老化知识库」输入道路宽度、休息、照明等关键词查看原文。协作助手不选择反馈时执行知识咨询，读取当前村庄档案与匹配片段；CodeBuddy 回答，Codex 独立复核。选择反馈后进入已有反馈—计算—草案—复核工作流。

本机安装的 rural-aging-evidence skill 提供同样的来源判断方法。skill 是复用的处理方法，知识索引是资料；网页通过服务端检索实际使用索引，不会因为安装 skill 就自动获得资料或执行能力。

重建索引：先执行 `python3 scripts/extract-knowledge-docx.py`，再执行 `npx tsx scripts/index-knowledge.ts`。脚本需要原始工作目录。私有索引位于 `work/knowledge.json`，不进入 Git 和网页构建。生产部署时由管理员复制该索引到私有持久卷，并配置 `KNOWLEDGE_PATH` 指向它；无索引时明确返回无匹配资料。

新增案例应包含原始出处、实施状态、片段定位、适用条件、不能支持的结论；有个人信息的材料先取得授权。新增条目后再由负责人核验，不能自动把资料变成适用规范。真实村庄的坐标记录不证明已做现场调查。
